- `DIVEComponent` is **not** an `Object3D` and is not in the scene graph. What it owns is: `contribute(...objects)` puts them into the *owner's* `children` and takes them along when the component moves nodes, `withdraw(...)` takes them back without disposing, and `component.contributions` lists them. `contributedBy(object)` and `findComponent(object, Ctor)` are the way back from contributed content to its component — a `WeakMap` in `Component.ts`, not a flag on the object, because `Object3D.copy` sends `userData` through JSON and `GLTFExporter` writes it out as `extras`
- The reason is the exporter: `GLTFExporter.processNodeAsync` has no skip for empty nodes, so a component in the graph cost one level per component per save, and on reload that level became content of a new component
- `DIVENode.addComponent`/`removeComponent` do the wiring themselves (`_attach`/`_detach`, `_components`, tick enrolment); three's `childadded`/`childremoved` no longer speak for components. `addComponent` steals from a previous owner explicitly, since `Object3D.add` used to do that via `removeFromParent`
- A `catch` has to transform, recover or clean up. One that only re-rejects is a no-op inside an `async` function and should go — but `DIVEAbortablePromise._execute` keeps its `catch` on purpose: the method is synchronous, so an executor throwing before its first `await` would throw at the caller instead of rejecting. Adding context means `throw new Error(msg, { cause })`, as `State.performAction` does — not a `console.error` before a rethrow, which makes one failure appear twice in a channel the caller did not choose. Every rejection carries a reason; `Promise.reject()` with no argument loses it entirely
- `disposeComponents(object)` (`src/helpers/`) is the single teardown path: it traverses for `isDIVENode` and disposes each node's components, because components are not in the graph. Nothing else frees a component's geometries, materials or textures — unparenting frees nothing and `Renderer.dispose` only drops bookkeeping. `Scene.dispose`, `EngineGateway.removeEntity` and QuickView's source swap all go through it. It unparents nothing, so a caller that is only moving something cannot destroy it by accident
- `AssetExporter` collects the animation clips itself, through `collectAnimations(object)` as the default for all three formats — a caller's `options.animations` still wins, since `...options` is spread after it. It has to be the exporter's job and not the caller's: whoever uses the exporter directly, without `EXPORT_SCENE`, would otherwise have to know to go looking. Clips reach a file only when passed at the top level, because `parseAsync` resolves each track against the subtree it is handed and `Object3D.animations` of a descendant is invisible to it. `collectAnimations` reads both places clips end up — `Object3D.animations`, which the asset loader fills, and the `animations` field of any component, matched structurally so a later component needs no change — and **rebinds each clip to the objects of the asset that holds it**. That rebinding is not optional: a track names its target, glTF makes those names unique only within one file, and `PropertyBinding.findNode` takes the first match walking the export root — so two models both holding a `Cube`, or one asset loaded twice, had the second model's clips animate the first model's objects. It targets uuids, which cannot collide, and clones the clip because a mixer is playing the original; what lands in the file is a node index, so written-out names are unaffected. `_exportUsdz` had no `animations` default at all while glb and gltf did, which lost the clips on the `AssetConverter`/AR path — USDZ bakes them into `xformOp` time samples, so it takes them as well
- `AssetExporter._hideNonProductGeometry` tests for **any** geometry, not `instanceof Mesh`: a group's link lines and a bounding box helper are `LineSegments`, and a class-based test left them in exported files. The layer decides, so product lines and points are exported. `ENFORCED_OPTIONS` overrides `onlyVisible` for all three formats — the pruning works by hiding, so `onlyVisible: false` would serialize exactly what was hidden. `_computeNormals` still tests `instanceof Mesh`, correctly: lines and points have no normals

- A withdrawal that arrives while `DIVEScene.tick` is iterating is recorded in `_withdrawn` (a `Set`, by identity) and applied after the loop. It must **not** be derived from `tick`/`tickEnabled` state: a component removed from its node still has both, so the old state-based compaction kept it enrolled — it ticked forever, with `owner` throwing, and a node moved between scenes ended up enrolled in both. `enlistComponent` deletes from `_withdrawn`, so withdraw-then-enlist inside one frame is a no-op
- `DIVENode.copy` clones the source's components and **disposes** the ones the copy already held — `DIVERoot` attaches a floor in its constructor and would otherwise end up with two. Contributed content is never cloned; the cloned component brings its own
- Component `clone()`/`copy(source)` is DIVE's own now, not `Object3D`'s. Constructors still take no arguments for that reason. A component holding state must override `copy`, and cloning used to be broken in a way no test caught: `Object3D.copy` added a clone of the source child on top of the constructor's, leaving two and a `_mesh` pointing at the empty one. Every stateful component overrides it now — `MeshComponent` (a material from `setMaterial`, copied into a fresh one so neither `dispose` frees the other's), `FloorComponent` (colour, visibility), `PrimitiveComponent` (rebuilds from a stored `DIVEGeometry` descriptor rather than sharing the built geometry), `DIVELightComponent` (through its own setters, so `PointLightComponent` mirrors onto the handle; intensity divided back out by the factor), `DIVECameraComponent` (layer mask, not `onSetCameraLayer` — that is a caller's wiring), `PerspectiveCameraComponent` (fov/near/far, not aspect), `MultiLineComponent` (material only: keys belong to the caller). `ModelComponent` is the exception — a load is async and `copy` is not, so it carries `url` and `animations` and the caller calls `setFromURL(clone.url)`; cloning the hierarchy would share geometries and materials with the source
- `DIVEComponent extends EventDispatcher<DIVEComponentEventMap>`, so a component reports on itself. `object-load` is dispatched by `ModelComponent`, not by the node, and is gone from `DIVEEntityEventMap`; the state layer listens via `node.getComponent(ModelComponent)` in `watchEntity`. That listener is bound to the component that exists when the entity is composed — swapping a mesh component later would silently stop the reports, and nothing does that today
- `MeshComponent._materialIsOwn` marks a material as coming from `setMaterial` rather than from loaded content. A configured material outranks the asset's (the caller has the schema before the file); one adopted from an earlier load must not be pushed onto the next
- `MeshComponent.dispose` has an explicit ownership policy: it owns the geometries, materials and **textures** of what it contributed. It collects them into sets first, because three allows `Material[]` per mesh and one glTF can point several meshes at one material or several materials at one texture. Disposing textures is safe because a load produces its own — `AssetCache` holds file bytes, not parsed results. The old code cast the first mesh's material to `MeshStandardMaterial` and called `dispose()` on it, which threw on an array (`this._material?.dispose is not a function`) and aborted the rest of `Scene.dispose`. `ModelComponent` now adopts a material only when the mesh carries a single one
- `BoundingBox` (`src/engine/boundingbox/`) is the measurement on its own: no graph, no owner, no visualisation. `enclose(objects)` is world-aligned, `encloseOriented(objects, frame)` is axis-aligned in a frame carrying another object's position and rotation but **not** its scale, so `size` stays the size in the scene. `box`/`size` are in the measured frame, `center`/`sphere` always world. Framing uses it: `computeEncompassingView(sphere)`, and `focusObject` / `COMPUTE_ENCOMPASSING_VIEW` build one with `new BoundingBox().enclose(node).sphere`
- `BoundingBoxComponent` holds one and adds the node: it always encloses its **owner** — no target parameter — and watches it via `childadded`/`childremoved` (this is how a finished asset load arrives), `componentadded`/`componentremoved` and `object-transform`. An event only marks the box stale; measuring happens on read, because a fifty-root glTF arrives as fifty `childadded` events. `refresh()` is only for changes nothing announces, e.g. `PrimitiveComponent.setGeometry` swapping `mesh.geometry` in place. It ticks only while a helper is visible. Both helpers have `matrixAutoUpdate = false` and get a matrix that cancels the owner's transform, so the drawing is correct wherever the component hangs
- `DIVENode` dispatches `componentadded`/`componentremoved` (payload `{ component }`). Added because three's `childadded`/`childremoved` say nothing about components, so nothing could observe what a node is made of
- `src/engine/` holds the machinery: `component/Component.ts` (the base class and the contribution registry), `node/Node.ts`, `scene/root/Root.ts`, plus scene, renderer, view and clock. `src/components/` holds only the concrete capabilities a caller picks from. The split follows the coupling: `Node` and `DIVEComponent` are two halves of one mechanism (`addComponent` → `_attach` → `owner.add`), and `Scene` drives the base class's tick list. - `SoftShadowComponent` (`src/components/softshadow/`) is a baked contact shadow, not a shadow map and not tied to any light: a `PRODUCT_LAYER_MASK` camera under the node looks straight up, an override material writes `1 - height / far` into alpha, and two separable blur passes land it on a plane. The trade is the bake, which is what makes it right for a model that stands still and wrong for one that moves

- The shadow plane's geometry is `rotateX(+Math.PI / 2)`, not `-`: the bake camera looks up, so its up vector is world +Z, and the plane's V has to run the same way or the shadow is mirrored along Z -- invisible on a symmetric model and obvious on anything else. The cost is a normal pointing down, hence `DoubleSide`. - Input devices and camera controllers are split. - `TiltController` (`@shopware-ag/dive/tiltcontroller`) maps `axis` on `orientation` absolutely and mirrored sideways: `azimuth = home − clamp(x / maxTilt.x) · π`, so tilting the device left turns the camera the other way round the target (`_seed` mirrors the same sign) (±`maxTilt.x` is the middle of the back from either side), `polar = home + clamp(y / maxTilt.y) · maxPolarOffset`. It eases in fraction space, not angle space, and seeds from the current camera pose when (re-)enabled, taking the nearer way round
- `TiltController` limits move along: a reported tilt past `maxTilt` is clamped and the excess goes into `_slack`, which shifts the limits with the device. Turning back therefore moves the camera immediately instead of first winding off the overshoot -- at the cost that the original neutral pose no longer maps to the front after an overshoot. A limit only drags along when the report moved mainly along its own axis (`|dx| > |dy|` against the previous report, neutral after a reset); past the other limit the tilt is only clamped, so a wobble that returns leaves no offset. The slack resets on `setHome()` and when the controller is turned back on
- `GyroInput` derives tilt from the screen normal relative to the neutral quaternion -- `y = atan2(-n.y, n.z)` (angle in the vertical plane), `x = atan2(-n.x, hypot(n.y, n.z))` (how far the normal leaves it) -- not from Euler deltas. The split is deliberate: the other way round (`x` as `atan2(-n.x, n.z)`) amplifies a sideways wobble by `1 / cos(y)`, so moving the device up and down turned the camera sideways: no 360-degree wraparound, no gimbal lock, in-plane spin ignored. Held upright, `gamma +20°` gives `x = -20°` (view turned left) and `beta +20°` gives `y = +20°` (view turned up). It recalibrates on `screen.orientation` change. In jsdom, tests stub `DeviceOrientationEvent` via `vi.stubGlobal` and define `screen.orientation`; a test that leaves `enable()` pending must `.catch()` it, because the teardown `dispose()` rejects it
- `GyroInput` filters what it reports: a low-pass timed by `event.timeStamp` (`smoothing`, default 15/s, `Infinity` = off) and then a play/backlash (`deadzone`, default 1°): the reported value follows the filtered one only once they are further apart than the deadzone and then trails by exactly that, so there are no threshold jumps. A calibration resets both to the reading. `TiltController.smoothing` defaults to 5 (was 10) for a calmer camera. `GyroInput.test.ts` builds its geometry tests with `{ smoothing: Infinity, deadzone: 0 }` and passes `timeStamp` through `orient()` via `Object.defineProperty` (it is a getter on `Event`)
- A gravity-only `GyroInput` (ignoring the compass heading, `x` as a steering-wheel roll) was tried so that turning around in the room would not move the camera; on a device it felt chaotic and was rolled back. Turning an upright device like a door is physically indistinguishable from turning around, so any heading-free variant loses that gesture

- `DIVEAssetCache<T>` (`src/engine/asset/cache/AssetCache.ts`) shares loaded values by URL with reference counting: a map URL → `{ promise, value, refs }`, loader and disposer injected. `acquire(url)` shares a load that is on its way or done; `release(url)` frees the value with the last reference (a value released by everyone while loading is freed on arrival, and a re-acquire before that shares the load); a failed load drops its entry so a retry loads again, and holds nothing, so a rejected acquisition is never released. - The texture cache behind `TextureAsset` is module-level and outlives each test of a file, so a suite that creates `DIVEScene`s must dispose them after each test and let pending loads settle, or later tests share earlier loads and load counts/dispose assertions break; an unconsumed `mockImplementationOnce` on a loader then leaks into the next test too. `Scene.test.ts` wraps `DIVEScene` in a tracking subclass (`disposeScenes()` in `afterEach`, and in the light/background `beforeEach` to drop the top-level scene's default load), `Environment.test.ts` and `EngineGateway.test.ts` track the scenes their setup helpers make
- When suites of one class need different module mocks in their shared `<Class>.test.ts`, the mock is made switchable instead of split into files: a `vi.hoisted` flag the suite's `beforeEach` sets, and a partial mock via `importOriginal` that returns the real implementation when the flag is on. Current cases: `Scene.test.ts` (`real.root` -> real `DIVERoot` for ticking, image based light and background; the construction tests keep the stand-in root), `Toolbox.test.ts` (`raycasterState.real` -> real `Raycaster` for the `raycast` suite), `State.test.ts` (`real.toolbox` -> real `Toolbox`, and `getActionClass` handed the real lookup from `real.actionRegistry` for the `reporting to subscribers` suite, reset in its `afterEach`), `EngineGateway.test.ts` (`loadAsset` switched between a mesh asset and an empty one for `group links`)
- QuickView's `softShadow` setting (default `false`) is stripped from the settings before `new DIVE(...)` and adds a `SoftShadowComponent` to the model node when that node is created; the node is reused across URI loads, so the shadow persists. Scene-state loads get no shadow. There is no QuickView getter for it: reach it via `quickView.model.getComponent(SoftShadowComponent)`. QuickView has no settings for the image based light or the background; callers use `quickView.scene.setImageBasedLight`/`setBackground`
